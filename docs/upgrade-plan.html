Upgrade Plan

Modernizing the CRM AI Sale Recording Auditor

A staged plan to move off end-of-life Python 3.8 / Debian 10 and bring dependencies to their current stable releases — with the risks and migration gotchas called out per step.

TL;DR — Python 3.8 and Debian 10 "Buster" are both end-of-life, and the newest releases of several of your libraries (boto3, urllib3, requests, mutagen) no longer support Python 3.8. The highest-value, lowest-risk move is: base image → Python 3.12 on Debian 12 "Bookworm", drop two obsolete packages, let the low-risk libraries float to latest, and test the four that jump a major version.

1 Current → target platform

Python
3.8.6→3.12
3.8 EOL since Oct 2024. 3.12 is supported until Oct 2028 (3.13 → Oct 2029 if you want the longest runway).
Base OS
Debian 10 Buster→Debian 12 Bookworm
Buster is EOL and only on archive.debian.org. Bookworm is the current stable and removes the archive workaround entirely.
Recommended base image: python:3.12-slim-bookworm. The slim variant keeps the image small; you already install the system libraries you need (ODBC, kerberos) explicitly.

2 Why the version is the linchpin

You can't upgrade the libraries without upgrading Python — the latest releases dropped 3.8/3.9 support:

Minimum Python required by latestYour affected packages
3.10+boto3, urllib3, requests, mutagen
3.9+pydantic, openai, pymongo, pyodbc

Your app imports mutagen and requests directly, so Python 3.10 is the hard floor for a full dependency refresh. Going to 3.12 gives comfortable headroom.

4 Packages to remove (not upgrade)

  • backports.zoneinfo — a Python 3.8-only backport. zoneinfo is built into Python 3.9+, so this becomes dead weight after the upgrade.
  • configparser — the standard library already ships configparser on Python 3; the pinned PyPI package is redundant.
  • lxml (verify first) — no import lxml exists in the source. If nothing transitive needs it, drop it instead of taking the 4→6 major bump.

5 Migration gotchas — beyond version numbers

Most likely to bite: the SQL driver. The Dockerfile installs msodbcsql17 from the Microsoft debian/10 repo. On Bookworm you switch to the debian/12 repo and msodbcsql18. Driver 18 defaults to Encrypt=yes, so sqlconnect.py needs the driver name updated to ODBC Driver 18 for SQL Server and the connection string will likely need TrustServerCertificate=yes (or a valid server certificate). Test the SQL connection early.
  • Remove the archive.debian.org workaround. The sources.list rewrite added for Buster is unnecessary on Bookworm and should be deleted.
  • apt-key is gone on Bookworm. The Microsoft signing key must be added via a signed-by=/usr/share/keyrings/... keyring instead of apt-key add -.
  • urllib3 2.x + verify=False. Several CRM calls disable TLS verification; expect changed/immaterial warning output. Functionally fine, but confirm during testing.
  • openai 1→2 and pyodbc 4→5. The two library majors worth an explicit smoke test — even though the OpenAI path is disabled and the chat.completions surface is unchanged.

6 Recommended execution order

  1. 1
    Branch & snapshot
    • Work on a branch (e.g. chore/upgrade-py312) — never on main.
    • Capture the exact working versions first: pip freeze inside the current container, so you have a rollback reference.
  2. 2
    Base image + Dockerfile
    • Switch to python:3.12-slim-bookworm, remove the archive workaround.
    • Repoint the Microsoft repo to debian/12, use a keyring instead of apt-key, install msodbcsql18.
    • Get a clean docker build before touching Python deps.
  3. 3
    Dependencies
    • Drop backports.zoneinfo and configparser; verify and likely drop lxml.
    • Pin only your direct dependencies to latest; let transitive ones resolve.
    • Update sqlconnect.py for the Driver 18 name + encryption flags.
  4. 4
    Test end-to-end
    • SQL connection (Driver 18), MongoDB, CRM auth, one real audit through the n8n webhook, and a report/alert to Google Chat.
    • Run against a small date window first; confirm de-dup still skips existing documents.
  5. 5
    Deploy
    • Build, tag, and push to the GCloud Artifact Registry as today.
    • Keep the previous image tag available for a quick rollback.
Safe fallback: if the Bookworm + Driver 18 migration proves fiddly under time pressure, a smaller interim step is python:3.10-bookworm with msodbcsql18 — it still gets you onto a supported OS and unblocks every latest library, with Python 3.10 as the minimum floor.
