2 What changed, file by file

FileChangeWhy
Dockerfile Base image → python:3.12-slim-bookworm. ODBC Driver 17 → 18, installed via the official packages-microsoft-prod.deb. Removed the archive.debian.org workaround and the deprecated apt-key usage. Consolidated apt layers and cleaned caches. Buster/3.8 are EOL; Bookworm/3.12 are supported. The .deb registers the MS repo with a modern signed keyring.
requirements.txt Rewritten to pin only the 12 direct dependencies at latest stable; transitive packages now resolve automatically. Removed 5 obsolete packages. Smaller, clearer dependency surface; fewer stale pins and CVEs.
src/sqlconnect.py Driver string → ODBC Driver 18 for SQL Server; added Encrypt=no to the connection string. Driver 18 defaults to Encrypt=yes; Encrypt=no preserves the exact behavior Driver 17 had, so the existing SQL Server keeps working unchanged.
src/main.py Suppressed urllib3 InsecureRequestWarning at startup. The CRM calls use verify=False; this quiets the (harmless) per-request warning. Behavior is unchanged.

Removed

  • backports.zoneinfo — a Python 3.8-only backport; zoneinfo is now built into the standard library.

4 What this improves

🛡️
Back on supported, patched software
Python 3.8 and Debian 10 stopped receiving security updates (Oct 2024 and mid-2024). Python 3.12 is supported through Oct 2028 and Debian 12 is current — you now receive OS and language security patches again.
⚡
Faster runtime
CPython 3.12 is meaningfully faster than 3.8 across the board, so each batch run does the same work with less CPU time.
📦
Smaller, cleaner image
The slim base plus removing 5 unused packages and cached apt layers means a smaller image — faster pulls, faster deploys, and a smaller attack surface.
🔒
Current library security & bug fixes
Every dependency moved to its latest stable release, picking up years of security patches and fixes in pydantic, openai, pymongo, requests/urllib3, boto3 and the SQL driver.
🧹
No more fragile build hacks
The archive.debian.org workaround and deprecated apt-key call are gone. The build no longer depends on an end-of-life mirror and uses the modern signed-keyring method for the Microsoft repo.
🧰
Easier to maintain
Pinning only direct dependencies means future upgrades are a short, readable list instead of 34 intertwined pins.

Rollback is clean: all changes live on the Upgrade-docker-and-requirement branch, so main and the previously deployed image are untouched. If anything misbehaves, redeploy the prior image tag or check out main.

7 Notes & follow-ups

  • SQL encryption: the connection uses Encrypt=no to match the old behavior. If/when your DBA enables TLS, switch it to Encrypt=yes;TrustServerCertificate=yes; for encrypted connections.
  • TLS verification (security, optional): the CRM calls still use verify=False; the warning is only suppressed, not fixed. Enabling proper certificate verification is a worthwhile future hardening step.
  • Unrelated open item: duplicate rows in the make.com sheet — handleTask currently calls both push_blank_call_to_make_report and push_to_make_report for every recording. Tracked separately from this upgrade.
