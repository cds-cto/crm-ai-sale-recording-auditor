Project Overview

CRM AI Sale Recording Auditor

A batch job that pulls sales-call recordings from the CRM, runs them through an AI compliance audit, and pushes pass/fail results with error details to reporting channels.

1 What it does

Debt-settlement sales calls must follow strict compliance rules — salespeople can't misrepresent the program (call it a government program, promise refunds, claim no credit impact, etc.). This service automates that review. On a schedule it collects newly uploaded recordings, sends each one to an AI auditor that listens for rule violations, and reports the verdict per call. Every result is logged so the same recording is never audited twice.

The whole thing runs as a single Python batch process (src/main.py) containerized with Docker and triggered by a scheduled cron job — there is no long-running server or user-facing UI.

3 End-to-end flow

  1. 1
    Kick off with a date window
    main.py builds a PDT window (last 15 days → tomorrow) and calls AISaleService.process().
  2. 2
    Wire up services
    Connect to MongoDB, log into the CRM API, and initialize the Auditor, Validation, Reporting and SQL services.
  3. 3
    Fetch the batch of recordings
    get_recordings_with_sql() runs one big SQL join and returns only calls that qualify: category = sale recording, recording status = Uploaded, an active profile, and a non-empty enrolled balance. Each row becomes a RecordingModel.
  4. 4
    Loop over each recording — handleTask()
    Load the compliance rule list from Mongo, then process every recording one at a time (see the per-recording flow below).
  5. 5
    Enrich & report
    Pull the profile's status and enrolled date from the CRM, then push the result to the Make.com webhooks (and optionally a Google Chat card).

4 Per-recording audit — handling()

  1. 1
    De-dup check
    If the document_id already exists in MongoDB, stop immediately — nothing is re-audited or re-reported.
    X100Already audited → skip & move on (no report sent).
  2. 2
    Validate the file
    Confirm the uploaded file is actually audio (.mp3 / .wav / .m4a).
    F101Not an audio file → log as failed & report, skip auditing.
  3. 3
    Prepare context
    Get the recording's download URL from the CRM, then compute the client's weighted settlement percentage and estimated pay-off amount from their liability profile — the auditor uses these to judge whether the rep quoted realistic numbers.
  4. 4
    Send to the AI auditor
    AuditorService.process() POSTs the recording URL, company, settlement %, pay-off amount and client name to the n8n webhook, which transcribes and evaluates the call against the compliance rules.
  5. 5
    Interpret the response
    Read back the error_code_list, transcript and duration.
    ✓ passEmpty error list → success = True.
    violationsOne or more errors → success = False, keep the error details.
    X101Auditor error / bad response → logged as failed.
  6. 6
    Log to MongoDB
    Write the full result document (verdict, errors, transcript, duration, metadata) — this both records the outcome and prevents re-auditing next run.
Note: The AWS Transcribe + OpenAI GPT path (transcribe_service.py, gpt_service.py) is the original in-house auditing pipeline. It's currently commented out — the live system delegates the whole transcribe-and-audit step to the external n8n webhook instead.

X101The AI auditor errored or returned an unusable response.

7 How it runs

Packaged as a Docker image (Python 3.8.6 with MS SQL ODBC drivers) and pushed to Google Cloud Artifact Registry. Cloud Scheduler triggers it on a cron schedule — an hourly run through the business day, plus a daily mass run — so recordings are audited automatically without anyone kicking it off. Each run exits when the batch is done.
